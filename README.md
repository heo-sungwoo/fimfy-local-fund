## 🎯 해결한 문제

> "소상공인이 특정 지역에서 창업할 때, 수익성·안정성·경쟁강도를 객관적으로 판단할 수 없다"

기존 상권 분석 서비스는 단순 매출 통계 제공에 그침.  
FIMFY는 ML 3개 모델로 자동 평가하고, LLM이 종합 심사 리포트를 생성함.

## 🗂️ 데이터 수집 및 통합

### 데이터 소스 (13종)
| 카테고리 | 데이터 | 출처 |
|----------|--------|------|
| 매출 | 추정매출 (분기별 행정동×업종) | 서울 열린데이터광장 |
| 인구 | 유동인구 / 상주인구 / 직장인구 | 서울 열린데이터광장 |
| 점포 | 점포수 / 개·폐업 / 집객시설 | 서울 열린데이터광장 |
| 지가 | 공시지가 | 서울 열린데이터광장 |
| 경계 | 행정동 경계 (공간데이터) | V-World |

### DB 통합 구조
```
공공데이터 13종 (CSV)
    → Oracle 11g 적재 (15개 테이블: DIM 5 + FACT 10)
    → SQL 전처리 (필터 / 조인 / 집계)
    → 마스터 테이블 (196컬럼 × 10,290행)
```

### 핵심 전처리 — 공시지가 공간조인
- 공시지가는 **법정동** 단위로 제공 → 분석은 **행정동** 단위 필요
- 위도/경도 기반 공간조인으로 법정동 → 행정동 매핑
- `WGS84 ↔ TM(EPSG:5181)` 좌표 변환 적용

## 📊 분석 체계

### 3가지 분석 표현 방식
| 방식 | 설명 | 목적 |
|------|------|------|
| 랭크(R) | 순위 기반 비교 | 상대적 위치 파악 |
| 비율(%) | 구성·점유 분석 | 내부 구조 파악 |
| 패턴(~) | 시간·요일 흐름 | 트렌드 파악 |

### 상관관계 분석
- 8개 그룹으로 피처 분류 → 그룹 내 상관 분석
- **0.8 이상 고상관 36쌍** 식별 → 다중공선성 관리

### 신빙성 검증 사례
> 역삼1동 × 중식음식점 → **서울 4위**  
> 실제 강남역 상권 인식과 일치 — 데이터 신뢰성 확인 ✅

## 🤖 밀집도 모델 (본인 담당)

**`kakao_density_V05.py`** — 동적 반경 기반 경쟁강도 분석

### 핵심 설계
- **고정 반경(500m) 방식 폐기** → 행정동 배후지 면적에 따라 동적 조정
- Kakao Local API로 실제 영업 중인 경쟁 업체 수집
- 경쟁강도 A/B/C 등급 분류 (전체 33% 기준)

### 기술 스택
```python
# 좌표 변환 (WGS84 → TM)
from pyproj import Transformer

# 동적 반경 계산
radius = calculate_dynamic_radius(area_sqm)  # 배후지 면적 기반

# Kakao API 호출
competitors = kakao_local_search(lat, lng, radius, category)

# 등급 분류
grade = classify_grade(competitor_count, total_distribution)  # A/B/C
```

### 출력 예시
```
업종: 짜장면 (중식)
위치: 중구
동적 반경: 422m
경쟁 업체 수: 12개
경쟁강도 등급: C (상위 33% 이상)
```

## 🏗️ ML 파이프라인 전체 구조

```
마스터 테이블 (196컬럼 × 10,290행)
    ├── M1. 수익성 모델 (AutoGluon) → ROC-AUC 0.92
    ├── M2. 안정성 모델 (AutoGluon) → ROC-AUC 0.82
    └── M3. 밀집도 모델 (Kakao API + 동적 반경) → A/B/C 등급
              ↓
    LLM 자동 심사 파이프라인 (LangChain)
              ↓
    펀딩 의사결정 리포트 생성
```

> ※ M1 수익성·M2 안정성 모델은 팀원 담당 / M3 밀집도 모델은 본인 담당
